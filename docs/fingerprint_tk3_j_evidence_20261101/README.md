## 1. 更正上一轮“所有状态均不匹配”的说法

此前用于诊断的`raw_j_references`函数会丢弃整条翻译含`*`或`X`的参考。它可以生成“无终止符参考”的列表，但不能用于宣称覆盖了所有F／ORF／P参考。

因此，上一轮关于4PRH“保留所有功能状态后也无精确J末端匹配”的说法需要撤回。**无F／(F)参考精确匹配仍是现有规则下的事实；无任何胚系参考解释则不成立。** [逐项更正及受影响字段](CORRECTIONS.json)明确区分二者；旧交付不覆盖或删除。

新建的证据读取器完整保留原始功能性标签、终止符、模糊密码子及位置，仅供审计，不参与准入。对固定的4份人／鼠TRAJ/TRBJ参考共178条记录检查，其中10条含终止符；本轮新取的人TRAJ FASTA与旧冻结文件逐字节一致，结论变化来自诊断读取遗漏，**没有换参考或改阈值**。

## 2. 原文与IMGT支持什么

[2010年原文](https://pmc.ncbi.nlm.nih.gov/articles/PMC2901058/)明确报告TRAV20／TRAJ58与TRBV9／TRBJ2-2组合，描述TK3、MW1、CS1这些天然克隆线索及来自三个无关个体的连接区序列，并说明TK3 cDNA从T细胞RNA克隆，常数区采用工程二硫键。功能和SPR证据并不支持“TK3因胚系ORF标签就没有功能”的判断。

[IMGT官方TRAJ表](https://www.imgt.org/IMGTrepertoire/LocusGenes/genetable/autotable.php?group=TRAJ&species=Homo+sapiens)仍将TRAJ58*01列为ORF；注释11说明，其胚系首个终止密码子可能在重排中消失。这里没有把数据库ORF改成F，也没有宣称已从TK3完整原始CDS直接证明某个核酸删除事件。

由此，4PRH的J端应表述为**“存在原文及TRAJ58下游序列依据，但不满足当前F-only参考规则”**，不能继续称为无法解释的异常末端。旧规则是保守协议约束，不是成熟受体生物学功能的金标准。原始完整重排核酸与全部工程构建体仍未补齐，外部配对编号仍缺。

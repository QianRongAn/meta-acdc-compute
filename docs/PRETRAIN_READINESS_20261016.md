**重训阻断项：先修这些，再谈实验数字**

**B1．现存VDJdb表仍保留185,117条假阴性，训练加载器仍接受。**

`data/processed/vdjdb.clean.tsv`共199,289条，label=1有14,172条，label=0有185,117条，缺少新confidence列；文件仍为9月20日旧产物。新导入器已正确把label留空、分流TRA/TRB和V/J；但没有作用到默认使用的旧文件。实测 `benchmark_baseline.load()`仍接受这份有标签旧表，不能靠“无标签拒跑”挡住它。

整改：保留旧文件作历史产物，用新导入器写入独立版本目录；新VDJdb输出只保留证据置信度和关联信息，不能把0当实验非结合。训练入口必须检查数据版本/标签来源，而不只检查label是否非空。真实结合任务仍需另取带assay和完整受体身份的标签。

**B2．IEDB“修复TSV”与真实CSV不符；旧处理表也没有重建。**

原文件 `data/raw/iedb/mhc_ligand_full.csv` 是9.2GB、逗号分隔、双行表头、112列。最新 `ingest_iedb.py`却硬编码 `delimiter="\t"`。用真实头和前两条记录的小样本执行，立即报 `ValueError: list.index(x): x not in list`。此前合成TSV用例通过，不代表能解析实际文件；“此前从未正确解析任何IEDB记录”的台账说法也缺乏依据，不能由这次错误倒推出历史全无有效产物。

旧 `iedb.clean.tsv`有2,302,095条，仍为9月21日产物，缺少新版终点/单位处理的可追溯证据。MHC配体结合/呈递标签也不能直接当TCR–pMHC结合标签。

整改：以真实双行表头验证CSV/TSV输入，支持显式delimiter或可靠检测；先校验必需字段，再写临时输出并原子发布，避免读入失败时截断目标文件。IC50、KD、速率、稳定性、呈递等终点应分别保存，不能仅凭方法中出现binding就认作IC50；单位和测量限定符、冲突、assay ID及PMID要可追溯。先真实小批次验收，再全量重建，不能直接覆盖旧225MB表。

**B3．主图缓存有15组完全相同的输入同时标正、负。**

对每个图的节点特征、坐标、边索引和边特征全部逐数组计算SHA256，发现15组跨标签重复，涉及41条图记录：15个正样本、26个负样本。例子：

- `1zgl_0`（正）与`1zgl_0<-5e6i_2`（负）完全相同。
- `2xn9`、`2xn9-disp`、`2xn9<-2vlr_0`完全相同，标签分别1/0/0。
- `6vm7`及其displaced/graft诱饵同样冲突。

另有11个正样本的肽标记节点数为0，名称保存在证据JSON。模型没有看到肽时，移动或嫁接肽可能根本不改变输入。这是已存在的数据标签矛盾，不只是“诱饵未经实验验证”的方法局限。

整改：图级至少要求可识别的肽节点和有效TCR–肽界面；生成后检查扰动实际进入模型输入。相同输入出现相反标签须拒收并记录原因，不能靠训练容忍。供体身份比较仍有 `resname[:1]` 残留；不同长度只交换前缀、缺骨架时保留原子却改残基名等情况也应核查。不能只删除这41行就宣布生成规则正确，必须修构建器后重建。

**B4．家族映射未更新，训练/验证仍有跨折重叠。**

现存映射291条、289组。按当前`receptor_sequences`重算，291条旧receptor_key均不匹配，得到262个可观测受体链集合键；21个集合被旧映射拆在不同family_id。模拟当前train_egnn的默认顺序与seed=42，5个集合跨训练/验证两侧，包括`3h9s/3pwp/3qfj`、`3mv7/4prp`等。

这5组中含单链记录（如`6ulr/7su9`），不能一概宣称是已验证完整αβ受体；它反而说明身份完整性还需核查。这里只是完全相同的可观测链键检查，尚未完成近缘序列家族隔离。多复合物文件的全文件链集合、重复拷贝和不完整构建体不能直接充当最终受体家族定义。

整改：为每个有效复合物保存独立链角色和完整受体序列；在该身份层生成确定性的家族/近缘聚类，重新建立映射。先冻结独立测试集合，再派生训练、验证、校准集合；增加AF3数据不能重新洗牌测试集。映射缺失或版本不匹配须失败，不能静默退回PDB分组。

**B5．域适应训练仍用旧分组函数。**

`train_domain_adapt.pdb_group()`仍把 `5brz`、`5brz_0`、`af3-5brz_EVDPIGHLY`返回为三个不同组，没有复用已修的train_egnn身份/家族逻辑。对现存234份角色检查通过的输入，按名称和当前分组函数模拟切分，97个PDB身份可能跨折。

97是**图构建筛选前的身份分组模拟结果**，不是宣称已经训练并量化了97个实际泄漏模型案例；图生成仍可能跳过输入。但函数本身的身份拆分错误已确定存在。该训练路径还没有与评分路径相同的QC闸门，native manifest可选，未提供或路径错误时过滤可能关闭。

整改：所有训练、域适应、评分、校准共享同一身份与冻结split manifest；预测结构必须来自经身份核验的native manifest并通过相应QC，不能因目录名叫positives就全部赋正类。预训练的图供体也需记录来源；严格unseen-entity任务应检查跨折供体序列暴露，而不只看图的受体名字。

不能说“所有图都完全没重建”：主缓存10月15日16:21确实更新过，1ao7抽查通过。但它只含graphs/labels/pdbs，无代码版本、源文件哈希、链映射、标签语义和切分manifest。

用**当前**结构选择/拆分规则复查原缓存392个正样本对应源结构，只能得到328个候选复合物身份；64个缓存身份已不在当前选择结果中。这里没有重建所有图，328也不是新的合格训练样本数。差异说明缓存与最新逻辑不一致，不能据一次抽查全面签字。

整改：统一版本化重建，旧图和权重保留历史目录但不得成为新训练默认输入；输出图级provenance、构建器SHA、源结构哈希、节点对应、诱饵供体和构建参数。每个新权重记录精确数据及split哈希，禁止通过文件名猜版本。

**B7．临床代码改了，默认案例表仍旧。**

代码CASES已把A118T两条记录的pdb置空；但现存`clinical_index_cases.tsv`仍将KVAELVHFL、KMVELVHFL挂在5brz。用代码生成新临时表的合成测试通过，不代表默认表已正确。

整改：在独立版本目录从修正定义生成案例表，并做代码定义↔发布表一致性检查。没有该受体的结构时明确未评分；历史分数/病例关联不能继续作为当前证据。

**B8．QC部分修好，但还不足以覆盖训练数据与所有模型。**

现有QC表261条，无重复联合键：全表147通过、96无置信依据、18低ipTM。188候选面板为93通过、84无依据、11低ipTM。新评分器正确拒绝缺记录和低质量实例，旧跨实例覆盖反例已通过。

仍有两点：QC默认未覆盖独立native预测目录/所有训练输入；置信度聚合至job且只解析model_0，不能保证同job每个model都合格。合成例子中高ipTM但CIF解析失败，QC仍输出空flag、tcr_ca=pep_ca=-1，后续可能被当PASS；现存QC表未发现这种行，不能说真实261条已有同样坏例。

整改：按真实来源与模型文件建立关联，结构解析失败、关键链或肽缺失必须显式拒收。链完整性要区分MHC I/II、单链构建体和融合链，不能用长度阈值或一律强制B2M来冒充生物学核验。源文件或QC策略变化即使旧表失效；质量阈值本身仍是工程策略，不能当结合证据。

**重训放行条件（必要项，不以23个单测代替）**

1. 明确任务：结构天然/人工诱饵判别可以使用结构来源标签；真实结合/非结合预测必须有相应assay来源、受体配对、MHC与实验终点，不能由诱饵或数据库置信度替代。
2. 完成构建器修复，再以新版本目录重建两张序列表、结构身份、家族映射与图；旧产物只读保留。真实CSV小批次、特殊残基、长度不同供体、缺原子、无肽界面都有回归验证。
3. 新图中无相反标签的完全重复输入；界面和肽节点满足事先声明的任务标准；图节点、坐标、边特征与当前源结构一致，并有可追溯记录。
4. 所有训练/域适应/校准共用冻结split manifest，测试先固定。复合物、重复结构、受体家族和任务要求的实体交集检查均通过；各折非空且可评估。
5. 所有预测结构在正确的来源和模型级别完成QC；标签与native来源核验独立于结构置信度。不能用“高ipTM”代替真实结合标签。
6. 文件SHA256、构建代码SHA、参数、标签语义、排除原因、集合划分、完整性/冲突检查写入release manifest；独立复核通过后再启动重训。当前检查结果明确为training_allowed=false。

这些条件意味着：应先做数据修复与冻结发布，不能直接把旧checkpoint清空后重新跑epochs。也不应该因为发现坏行就无痕删掉：保留原始证据、版本化排除清单和旧结果，才能解释新旧结果变化。
